# Elmo Drive Control State Machine

A useful video to understand the control process state machine [[CiA 402 State Machine](https://www.youtube.com/watch?v=erQU5UeqMU8)]

The two motor drives on the leg are Elmo servo drives, and like any CiA-402 (aka DS-402) drive they sit behind a device state machine. A drive ignores velocity and torque commands until it has been walked into the Operation Enabled state, and reaching that state means reading the drive's status word each cycle and writing back an appropriate control word until it climbs through the intermediate states. This module is the pure logic for that handshake. It deals only in integers, a status word in and a control word out, with no bus code and no stored state, so it reads and tests on its own.

`drive_state` takes the status word that arrives in the input PDO and decodes which CiA-402 state the drive is currently in, returning a single `DriveState`. The decode is a set of bit-mask comparisons taken directly from the baseline Elmo state machine in the Simulink model, where each state has a known fingerprint in the lower status-word bits. The baseline spread this across several boolean flags; here it is one enum value carrying the same information, and anything that matches no known fingerprint comes back as `UNKNOWN`.

`control_word_for` is the other half. Given the decoded state it returns the control word to send so the drive moves toward Operation Enabled. The climb is incremental: a shutdown to reach Ready to Switch On, then switch on, then enable operation, with each step adding one more control bit. A faulted drive is told to reset, and an already enabled drive is held in place with the same enable word. These are the exact transitions the baseline drive used, kept as a small lookup table rather than a chain of conditionals, and an unrecognised state falls back to disabling voltage, which is the safe default.

`control_word` ties the two together and is the entry point the rest of the stack uses. Each cycle the EtherCAT interface hands it the incoming status word and the current master-enable flag; it decodes the state, applies the enable and internal-limit override, and returns the word to pack into the outgoing frame. A cleared enable or an active limit bit forces the drive back down with a shutdown, and otherwise the climb toward Operation Enabled proceeds. This is the one override the baseline kept outside its state machine, and it is the hook a future deadman or e-stop would drive.

Nothing here decides when to enable the drives or touches the bus; that is the EtherCAT interface's job. It supplies the enable flag and the status word, calls `control_word` every tick, and packs the result alongside the motor command. Because the control word is re-derived from the status word on every tick, the machine recovers on its own without remembering anything.
